UI Changes Overview

New pages, modified pages, and gating changes across the app

New Pages

NEW
/request-access
Request Access Page
Replaces the current "Create Account" dialog on the login page. Full page with fields: Full name · Work email · Department · Reason for access. Submit stores to access_requests. On return visit, shows "Your request is pending approval" or rejection note if actioned.
NEW
/set-password
Force Password Reset Page
Shown automatically after first login when must_reset_password: true. Cannot be skipped — all other routes redirect here until complete. Fields: New password · Confirm password. Live policy checker shows which rules are met (length, uppercase, number, symbol). On submit, validates against policy + no-reuse check, then redirects to /landing.
NEW
/admin
Admin Console
Dedicated route, visible in sidebar only for Admin-role users. Four tabs:

Users tab — table of all users (name, email, roles, status, last login). Actions: Create User (form: name + email + roles → generates temp password shown on screen), Edit roles, Disable/Enable, Delete.

Requests tab — badge shows pending count. Table of access requests with status. Approve action opens modal: assign roles (multi-select) + confirm. Reject action opens modal: optional rejection note.

Password Policy tab — form to configure: min length slider, complexity toggles, no-reuse count, expiry days. Save button persists to password_policy collection.

Audit Log tab — read-only table: who did what and when (logins, role changes, approvals, password resets).

Modified Pages

MODIFIED
/login (login.tsx)
Login Page
"Create an account" button → replaced with "Request Access" link that navigates to /request-access. Register dialog removed. Login now calls POST /api/auth/login (FastAPI) instead of reading localStorage. On success, JWT stored as httpOnly cookie.
MODIFIED
AuthContext.tsx
Auth Context
Stripped of all localStorage logic. Now wraps API calls: login() → POST /auth/login, logout() → POST /auth/logout, register() removed. User object gains roles: string[] and must_reset_password: boolean. Exposes hasRole(role) and hasAnyRole(...roles) helpers.
MODIFIED
App router
Route Guards
Two new wrapper components: <RequireAuth> (redirects to /login if not authenticated) and <RequireRole roles={[...]}> (shows 403 page if user lacks required roles). /admin wrapped with RequireRole roles={["admin"]}. Force-reset check: if must_reset_password is true, all protected routes redirect to /set-password.
MODIFIED
Sidebar / nav
Navigation
Admin Console link added to sidebar under a separate "Admin" section — only rendered when hasRole("admin") is true. Requests tab badge count fetched on mount. User avatar/name shown in sidebar footer with logout button.

Role Gating (existing pages)

GATING
Write actions hidden/disabled for Viewer
Create, Edit, Delete, Upload buttons are hidden (not just disabled) when the user lacks the required role. Read-only state is rendered instead. Uses hasAnyRole() from AuthContext inline on each page.
GATING
Manager-only actions
Delete buttons, Close/Resolve issue, Accept/Dismiss validation queue items — hidden unless user has "manager" or "admin" role.
