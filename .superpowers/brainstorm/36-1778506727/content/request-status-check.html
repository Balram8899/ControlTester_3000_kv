How does a returning user check their request status?

They submitted a request — they're back. What do they see?

A

Email lookup on the same page

The request page has a small "Check status" section. User types their email → sees only their own status. No login required.

/request-access
Request Access
[ Full name · Email · Department · Reason ] → Submit
Already submitted?
your@email.com
Check
⏳ Your request is pending review by an administrator.

Pros

  • No friction — no token to remember
  • Works even if browser cleared

Cons

  • Anyone who knows your email can check your status
B

Token stored in localStorage after submit

After submitting, a request token is saved to localStorage. When the user returns, the page auto-detects the token and shows only their status — no email input needed.

/request-access — returning user
⏳
Request submitted
Your request for jane@kpmg.com is pending admin approval.
← Back to login
/request-access — after rejection
❌
Request not approved
Reason: "Role not applicable for current project."
Submit a new request or contact your admin.

Pros

  • Zero friction on return — auto-detected
  • Status tied to this browser only — more private

Cons

  • Cleared if browser/localStorage wiped
  • Doesn't work across devices
Either way: only status + optional rejection note is shown — no other request details, no other users' data.
